# 引言 —— 为什么要拆解一个编程代理？

*学习代理工程最好的方式，就是去研究现存最强的那个代理 —— 贴近地、机械地、逐行地研究。*

2025 年下半年，「AI 编程工具」不再意味着自动补全，而是开始意味着**一个能连续运行数小时的自主工程师**：读你的代码仓库、做规划、改动几十个文件、跑测试、修正自己的错误，然后交付。Claude Code 就是这一理念的参考实现。无论你在构建什么 —— 编程代理、研究代理、客服代理，还是内部自动化 —— Claude Code 都已经在生产环境中解决了你即将撞上的那些难题。

所以这本书要做一件不寻常的事。它把一个能正常工作、业界顶尖的代理拆开，向你展示底层的机制：它的提示词是怎么组织的，一条用户消息如何变成一个 API 请求，它如何在一个 200K-token 的会话中保持清醒，为什么它 60% 的指令描述的是**不该**做什么，它如何在不污染自身上下文的前提下委派给子代理（sub-agent），以及自主代理在真实环境中失败的七种具体方式 —— 每一种都配有一个已在真实运行框架中验证过的修复方案。

## 这是什么

一本**实战指南**，不是教程。每一章都遵循相同的结构：

1. **机制** —— 系统实际在做什么，配有具体物料：文件名、版本号、token 数量、触发条件。绝不含糊其辞。
2. **拿去用** —— 如何把那套机制移植进**你的**代理、你的 `CLAUDE.md`、你的提示词栈。

书中的这些模式，提炼自对 Claude Code 110+ 个提示词文件的公开逆向工程、对其请求流水线的源码级追踪，以及 Anthropic 官方发布的关于长时运行代理框架的指南。它们被组织成了你可以直接动手用起来的形态。

## 这本书写给谁

- 那些**在 Claude 或 OpenAI API 之上构建代理**的工程师 —— 他们想要生产级的模式，而不是重新发明轮子。
- Claude Code、Cursor 或同类工具的**高级用户** —— 他们想理解、并进而驾驭自己每天依赖的这台机器。
- 任何一个，曾眼睁睁看着自主代理对一个半成品任务自信地宣告大功告成，心里想着：*这事儿肯定有现成的解法。*（确实有。第 6 章。）

这不是一本 LLM 入门书。你应该已经知道什么是系统提示词、什么是工具调用。在此之上的一切，我们会逐步搭建起来。
